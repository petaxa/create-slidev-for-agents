# Slide authoring instructions

このプロジェクトでスライドを作成・変更する LLM は、次のワークフローと確認待ちを守ってください。ユーザーの明示的な確認を受けるまで、次の工程へ進んではいけません。

## 作成ワークフロー

1. ユーザーが `specs/_prot.md` に発表全体のプロットを書く
2. LLM が `DESIGN.md`、`specs/README.md`、`specs/_prot.md` を読み、各ページの `specs/NN_name.md` を作る
3. LLM は仕様の一覧と判断が必要な点を示し、ユーザーによる仕様確認を待つ
4. ユーザーが仕様を承認した後、LLM が `pages/NN_name.vue` を作り、`slides.md` に発表順で登録する
5. LLM はビルドと表示を確認し、ユーザーによる実装確認を待つ
6. ユーザーが `specs/_feedback.md` にフィードバックを書く
7. LLM がフィードバックの全項目を `specs/*.md` と `pages/*.vue` の両方へ反映し、必要に応じて `slides.md` も更新する
8. LLM が静的検査、ビルド、全スライドの表示を再確認して完成とする

`_prot.md` から仕様を作る工程と、承認済み仕様からページを作る工程を混ぜないでください。仕様確認前に `pages/` を実装せず、実装確認前にフィードバックを推測して修正しません。

## 作業前に読むファイル

- 仕様作成時: `DESIGN.md`、`specs/README.md`、`specs/_prot.md`
- ページ実装時: 上記に加え、実装対象と同名の `specs/NN_name.md`
- フィードバック反映時: 上記に加え、`specs/_feedback.md` と対象の `pages/NN_name.vue`

## 仕様と実装の同期

`pages/NN_name.vue` と `specs/NN_name.md` は、番号と名前を一対一で対応させます。ページの目的、内容、構成、表示順を変える場合は、Vue ファイルだけでなく対応する仕様も更新してください。

新しいページを追加するときは仕様と Vue ファイルを同時に作り、`slides.md` に登録します。ページを削除または改名するときも、仕様、Vue ファイル、`slides.md` を同じ変更の中で揃えます。

ユーザーの依頼と仕様が矛盾する場合はユーザーの依頼を優先し、仕様を先に、または実装と同じ変更の中で更新します。仕様にない主張、数値、画像、構成を既存ページの見た目から推測して追加してはいけません。不明点がページの目的や内容を変える場合は、推測せずユーザーへ確認してください。

## 実装と検証

共通の構造、コンポーネント、スタイルは `DESIGN.md` の「実装で利用する部品」に従って再利用します。ページ固有の都合でデザイントークンや共通レイアウトを複製しません。

実装後は次を行います。

1. `vp check` でフォーマット、lint、型検査を行う
2. `vp run build` で Slidev をビルドする
3. 全ページを表示し、文字のはみ出し、意図しない改行、要素の重なり、画像の欠落、クリック後の崩れがないことを確認する
4. `specs/_feedback.md` の各項目が仕様と実装の両方へ反映されたことを照合する

検証で問題が見つかった場合は、対応する仕様と実装を揃えて修正し、検証をやり直してください。
