# Editorial Paper デザインガイド

このテーマは、白い紙面に濃いインクで編集された技術冊子をイメージする。装飾を増やして華やかに見せるより、余白、文字の大きさ、細い罫線で情報の順序を明確にする。

特定の発表内容に依存せず、このテンプレートで一貫したスライドを作るためのルールをまとめた文書である。

## LLM が編集する前に

LLM は、この文書だけでページ内容を推測せず、`specs/README.md` と編集対象に対応する `specs/NN_name.md` を必ず読んでください。スライドの文章と構成は、そのページ仕様を見ながら実装します。

ページの目的や構成を変更した場合は、`pages/NN_name.vue` と `specs/NN_name.md` を同じ変更の中で更新します。新しいページにも対応する仕様ファイルを作ります。

## 1. デザインの原則

### 一枚につき、ひとつの主題

最初に、そのページで聞き手に理解してほしい一文を決める。本文、図、コードはその一文を支える要素だけに絞る。主題が二つある場合はページを分ける。

### 情報階層は位置と文字サイズで作る

固定見出し、主題、補足の順に視線が動くように配置する。色付きのカード、バッジ、アイコンを足して階層を作らない。強調したい語は太さとジャンプ率で扱う。

### 余白を内容として扱う

空いている領域を埋めない。左上の固定見出し、中央の主題、下端のフッターが作る大きな三角形を基本の構図とする。図や文章が小さい場合も、中央に寄せて静けさを保つ。

### アクセント色には役割を持たせる

ティールは選択中の状態、流れの一部、コードのプロンプトなど、意味がある箇所だけに使う。見栄えを整える目的で見出し全体を着色しない。

### コードは独立した対象として見せる

コードやコマンドを本文に埋め込まない。暗い背景のコードブロックを中央付近に置き、操作対象として認識できる大きさを確保する。

## 2. ビジュアルトークン

実装値は `styles/tokens.css` に置く。ページ固有の Vue ファイルへ色を直接書かない。

| 用途            | 値                          | 意図                       |
| --------------- | --------------------------- | -------------------------- |
| Paper           | `#fffdfa`                   | 真っ白より少し温かい本文面 |
| Warm paper      | `#f6f1ea`                   | 周辺の薄い陰影             |
| Ink             | `#121722`                   | 見出しと本文の主色         |
| Muted ink       | `rgba(48, 47, 44, 0.60)`    | 補足、番号、メタ情報       |
| Rule            | `rgba(123, 116, 104, 0.46)` | 見出しとフッターの罫線     |
| Accent          | `#2f7f7a`                   | 選択状態や方向を示す色     |
| Code background | `#151a22`                   | コマンドとコードの背景     |
| Code ink        | `#e9e4d8`                   | コード本文                 |

背景は `#fffdfa` を中心に、暖色のグラデーションと極小のドットを重ねる。テクスチャのコントラストは低く保ち、プロジェクターで模様が目立つ場合はドットの `opacity` を下げる。

## 3. タイポグラフィ

### サンセリフ

本文と見出しは、OS 標準のサンセリフを使う。

```css
"Helvetica Neue", Arial, "Hiragino Kaku Gothic ProN", "Hiragino Sans",
"Yu Gothic", Meiryo, sans-serif
```

外部フォントを必須にしないため、ネットワークがない会場でも同じ構造を保てる。日本語と英数字で字面が大きく変わる場合は、実際に投影する OS で確認する。

### 等幅フォント

番号、フッター、コードには `Courier New, Courier, monospace` を使う。等幅フォントは補助情報に限定し、長い日本語本文には使わない。

### サイズの目安

| 要素                 | 基準値         |
| -------------------- | -------------- |
| 表紙タイトル         | `5.45rem`      |
| 章扉タイトル         | `5.2rem`       |
| 主題                 | `3.5rem`       |
| ページタイトル       | `3.35rem`      |
| コードページタイトル | `3.2rem`       |
| 本文                 | `1.18rem` 以上 |
| 固定見出し           | `1rem`         |
| フッター             | `0.62rem`      |

主題が収まらない場合は、まず文章を短くする。次に改行位置とレイアウトを見直す。文字を小さくするのは最後の手段とする。

## 4. 画面の骨格

16:9 の画面を前提に、次の固定位置を守る。

- 左右の基本マージンは `3.95rem`
- 固定見出しは上から `2.65rem`
- フッターは下から `3.15rem`
- 本文開始位置は上から `6.6rem`
- 主題中心のページは垂直方向の中央へ置く

左上には短い現在地と水平線を置く。フッターには発表名と長い水平線を置く。この二本の線がページ間のリズムを作る。

## 5. レイアウトの使い分け

### 表紙

`<DeckSlide layout="cover">` を使う。タイトル、章番号、フッターだけで構成し、副題や説明を詰め込まない。タイトルは左寄せを基本にする。

### 章扉

固定見出しを外し、章名だけを中央に大きく置く。前後の密度を切り替えるページとして使う。

### 主題

`<DeckSlide section-label="...">` の中央に一文を置く。強調語は `<strong>` で一段大きくする。強調語を増やしすぎない。

### 要点一覧

三つ前後の並列項目は、番号、短いキーワード、説明の三列で並べる。各行は細い罫線で区切り、箱で囲まない。`v-click` は一行ずつ理解させたい場合だけ使う。

### 時系列と手順

連続した出来事は一本の水平線とノードで示す。線の上に別の情報を重ねない。四段階を超える場合は、二ページに分けるか、説明を減らす。

### 比較

二つの対象は `deck-split` を使い、上罫線で列を始める。背景付きカードは使わない。差分を文章で説明し、項目数を揃えることだけを目的に内容を増やさない。

### コードとコマンド

`CommandBlock` を使う。コードブロックはページ中央付近へ置き、上に操作目的、下に短い補足を置く。複数のコマンドを一枚へ押し込まず、実行順にページを分ける。

### 終了

最後のページは短い言葉だけで閉じる。連絡先やリンクが必要なら、その前に独立した案内ページを作る。

## 6. 文章のルール

- ページタイトルは内容を直接表す名詞句を優先する
- 主題は一度読めば意味が取れる長さにする
- 補足は主題の言い換えではなく、条件や具体例を書く
- 英語の小見出しは、内容理解に必要な場合だけ使う
- 抽象語を並べたスローガンを避ける
- 三項目に揃えるための項目を足さない
- 受け身を減らし、誰が何をするかを明確にする

句読点や記号を装飾として多用しない。矢印は実際の方向や因果を示す図だけに使う。

## 7. モーション

ページ遷移は `slide-left` を標準とする。`v-click` は説明順に意味があるときだけ使う。すべての要素を順番に表示すると、話すテンポより操作が目立つ。

## 8. 図と画像

図は主題の理解を早める場合に使う。人物、端末、ファイルなどを表す場合も、形と色の種類を増やしすぎない。線の交差と斜めの接続を避け、ラベルを対象の近くに置く。

画像を使う場合は `public/images/` に置き、縦横比を保つ。ロゴや証拠画像を装飾目的で切り抜かない。ひとつの写真を複数ページで反復しない。

## 9. 避ける表現

- 丸角カードを並べたダッシュボード風の構成
- 意味のないグラデーション文字や蛍光色
- 見出し、キッカー、バッジ、脚注を同時に置く過剰なメタ情報
- 小さな本文でページを埋めること
- 装飾用の矢印、アイコン、区切り記号
- 主題より強い影や背景テクスチャ
- ページごとに異なるフォント、マージン、罫線幅

## 10. 実装ルール

- スライド順は `slides.md` で管理する
- 各ページは `pages/NN_name.vue` に置く
- ページ共通の構造は `layouts/` に置く
- 再利用する表示や操作は `components/` に置く
- 状態を持つ処理は `composables/` に置く
- 色、フォント、余白は `styles/tokens.css` で変更する
- ページ固有の CSS は必要な場合だけ `scoped` で追加する
- 同じセマンティクスと配置が二回現れたら共通パターンへの切り出しを検討する

### 実装で利用する部品

例示ページがなくても共通 API と既存パターンを判断できるよう、次を基準とする。

| 目的             | 利用する部品                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------- |
| 全ページの外枠   | `DeckSlide` をルートに置く                                                               |
| 表紙             | `DeckSlide` の `layout="cover"`、`section-label`、`title` を使う                         |
| 通常ページ       | `DeckSlide` の既定レイアウトを使い、必要に応じて `section-label`、`title`、`lead` を渡す |
| 垂直中央配置     | `DeckSlide` の `variant="center"` または `variant="statement"` を使う                    |
| 章扉             | `deck-section-cover` と `deck-section-cover__title` を使い、固定見出しを置かない         |
| 一文の主題       | `deck-centered`、`deck-statement`、`deck-note` を使う                                    |
| 要点一覧         | `deck-recap` とその `__index`、`__keyword`、`__text` を使う                              |
| 四段階までの流れ | `deck-timeline` とその `__item`、`__label`、`__title` を使う                             |
| 二項比較         | `deck-split` とその `__column`、`__title`、`__text` を使う                               |
| 単一コマンド     | `CommandBlock` の `command` prop を使う                                                  |

`DeckSlide` のフッターは、指定がなければ `deck.config.ts` の `footerLabel` を使う。ページ固有のフッターが必要な場合だけ `footer-label` で上書きする。

文章や HTML を既存クラスへ無理に当てはめない。仕様に必要な表現が既存パターンにない場合は、二ページ以上で再利用するかを判断してから `components/` または `styles/patterns.css` へ追加する。一ページだけで使うスタイルは、そのページの `scoped` CSS に置く。

`v-click` は表示順に説明上の意味がある要素だけへ付ける。繰り返し要素は配列と `v-for` を使い、表示文言と構造を分離する。画像は `public/images/` に置き、Vue からは `/images/...` で参照する。

## 11. 完成前の確認

- 一枚ごとの主題を一文で説明できるか
- タイトルと本文が同じことを繰り返していないか
- 固定見出しとフッターの位置がページ間で揃っているか
- 投影サイズで本文とコードが読めるか
- 意図しない改行、はみ出し、要素の重なりがないか
- 罫線、図、ラベルの接続がずれていないか
- クリック表示を最後まで進めてもレイアウトが崩れないか
- 画像やコードの出典・権利を確認したか
