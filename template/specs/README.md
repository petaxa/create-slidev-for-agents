# スライド仕様の管理

`specs/` は、発表全体のプロット、各スライドの仕様、実装後のフィードバックを、Vue の実装とは分けて管理する場所です。

## ファイルの役割

| ファイル       | 記入者   | 役割                                                         |
| -------------- | -------- | ------------------------------------------------------------ |
| `_prot.md`     | ユーザー | 発表の目的、対象者、制約、スライドの流れを決める             |
| `NN_name.md`   | LLM      | 一枚ごとの目的、内容、レイアウト、振る舞いを実装前に定義する |
| `_feedback.md` | ユーザー | 仕様と実装を確認した後の修正指示をまとめる                   |

`_prot.md` と `_feedback.md` はページ仕様ではないため、`pages/` に対応ファイルを作りません。

## 作成順序と確認待ち

1. ユーザーが `_prot.md` を書く
2. LLM が `_prot.md` から全ページの `NN_name.md` を作る
3. ユーザーが仕様を確認する
4. LLM が承認済みの仕様から `pages/NN_name.vue` を作り、`slides.md` に登録する
5. ユーザーが実装を確認する
6. ユーザーが `_feedback.md` を書く
7. LLM がフィードバックに沿って `NN_name.md` と `pages/NN_name.vue` の両方を修正する
8. LLM が検査、ビルド、表示確認を行い、完成とする

LLM は手順 3 と手順 5 で作業を止め、ユーザーの明示的な確認を待ちます。仕様の作成と Vue の実装を一度に行ってはいけません。

## ファイルの対応

`pages/` とページ仕様は、ファイル名を一対一で対応させます。

```text
pages/03_statement.vue
specs/03_statement.md
```

番号は `slides.md` の発表順に合わせ、二桁以上のゼロ埋めを使います。同じ番号の重複を避け、ページの追加、削除、改名では `pages/`、`specs/`、`slides.md` を同時に更新します。

## ページ仕様の書式

新しい仕様は、次の雛形を基本にします。

```markdown
# NN ページ名

- 実装: `../pages/NN_name.vue`

## 目的

このページを見た聞き手に、何を理解してほしいか。

## 表示する内容

必要な文章、数値、コード、図、画像。未確定の内容は未確定と明記する。

## レイアウト

要素の位置、強調、余白、表示順。

## 振る舞い

`v-click`、操作、アニメーション。なければ「なし」。

## 維持すること

変更時にも崩してはいけない意図。
```

必要に応じて「出典」「前後ページとの関係」「未確定事項」を追加します。項目を埋めるための内容を推測で書き足しません。主張、数値、引用、画像には、ユーザー提供の素材または確認可能な出典を紐づけます。

## フィードバックの反映

LLM は `_feedback.md` の各項目について、次を確認します。

- 内容や意図の変更を対応する `specs/NN_name.md` へ反映したか
- 仕様の変更を対応する `pages/NN_name.vue` へ反映したか
- 追加、削除、並び替えを `slides.md` へ反映したか
- 画像や外部情報の追加に必要な出典を記録したか
- 修正後に静的検査、ビルド、表示確認をやり直したか

フィードバックの一部だけを Vue ファイルへ直接反映して、仕様を古いまま残してはいけません。
